# Published content read through platform adapters

Reading back what a platform has already published is routed through the same platform adapter that connects and publishes to it, resolved from the one registry, so a platform is readable only when it is supported. What the adapter returns is a platform-neutral published item — external ID, caption, media, preview, permalink, publication time, and whatever engagement figures the platform itself reports — instead of the legacy Instagram-shaped post that previously crossed this seam. Whether that read exists at all is a declared capability, not an inferred one: an adapter that does not report published history is never asked for it, and the caller receives an explicit unsupported answer rather than an empty feed, because an account that has published nothing and a platform that will not say are different facts the app must not show alike. The same rule governs engagement: a figure the platform omits stays absent, never a fabricated zero. The legacy Post shape survives only as a transitional mapping in the shell, where the library, calendar, and dashboard still render it.
